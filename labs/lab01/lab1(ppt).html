Семантическое версионирование

Формат версии:

МАЖОРНАЯ_ВЕРСИЯ.МИНОРНАЯ_ВЕРСИЯ.ПАТЧ

Правила увеличения версия:

  • МАЖОРНАЯ — обратно несовместимые изменения API
  • МИНОРНАЯ — новая функциональность без нарушения совместимости
  • ПАТЧ — обратно совместимые исправления

Дополнительные обозначения: предрелизные и билд-метаданные

Общепринятые коммиты

Спецификация Conventional Commits — соглашение о написании сообщений коммитов.

Структура:

<тип>(<область>):<описание изменения>
[необязательное тело]
[необязательный нижний колонтитул]

Основные типы:

Тип Назначение SemVer
feat новая функция MINOR
fix исправление ошибки PATCH
BREAKING CHANGE несовместимое изменение MAJOR

Основные команды Git

Изучены основные команды git:

Работа с репозиторием:

  • git init # создание репозитория
  • git status # состояние рабочего каталога
  • git add . # добавить все изменения
  • git commit -am # сохранить изменения
  • git push # отправить в удалённый репозиторий
  • git pull # получить обновления

Работа с ветками:

  • git branch # работа с ветками
  • git merge # слияние веток
  • git branch -d # удалить ветку

Gitflow Workflow

Освоен рабочий процесс gitflow:

  • master — официальная история релизов
  • develop — объединение всех функций
  • feature — отдельные функции
  • release — подготовка выпуска
  • hotfix — срочные исправления

Основные команды:

  • git flow init — инициализация
  • git flow feature start/finish — работа с функциями
  • git flow release start/finish — работа с релизами
  • git flow hotfix start/finish — срочные исправления

Соглашение об именовании Denote

Базовая схема:

DATE==SIGNATURE--TITLE__KEYWORDS.EXTENSION

Поля:

  • DATE — YYYYMMDDTHHMMSS
  • SIGNATURE — буквенно-цифровая подпись (необязательно)
  • TITLE — заголовок через дефис
  • KEYWORDS — ключевые слова через подчёркивание

Пример:

20260912T143025--otchet-po-laboratornoy-rabote__latex_report.md
